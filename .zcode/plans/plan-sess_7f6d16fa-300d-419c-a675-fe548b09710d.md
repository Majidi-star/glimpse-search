# v0.1 Implementation Plan — Glimpse Local Semantic File Search

Build milestone **v0.1** of the spec: Windows, text/Markdown/code/PDF only, hybrid search, tray + search popup, Locations + File Types settings, resource governor active, Max Effort button. No LLM, no images, no video.

## Tech stack (confirmed)
- Python 3.11 (present), managed by **uv** + `pyproject.toml`
- `sqlite-vec` (vector search in SQLite) + SQLite **FTS5** (keyword/BM25)
- Embeddings: `bge-small-en-v1.5` via `sentence-transformers` (384-dim, CPU, auto-downloads to HF cache). Wrapped behind an `Embedder` interface so v0.3's bundler/downloader can swap it.
- Extraction: `pypdf` (PDF, pure-Python). Code/text/MD: stdlib only, language-aware chunking.
- Watching: `watchdog`. Governor: `psutil` (+ `pynvml` if available, else skipped).
- GUI: **FastAPI** on localhost + **pywebview** native window. Tray: `pystray`. Global hotkey: `keyboard`.
- Small HTML/JS/CSS frontend (vanilla, no framework) served by FastAPI.

## Implementation steps (in order)

### 1. Project bootstrap
- `pyproject.toml` with uv: name `glimpse`, python `>=3.11,<3.12`, deps below, ruff config, optional `[project.scripts] glimpse = "glimpse.__main__:main"`.
  - Runtime: `fastapi`, `uvicorn`, `pywebview`, `pystray`, `pillow` (tray icon), `keyboard`, `watchdog`, `psutil`, `pynvml`, `pypdf`, `sentence-transformers`, `torch` (CPU), `sqlite-vec`, `pydantic`.
  - Dev: `pytest`, `ruff`.
- `.gitignore` (`__pycache__`, `.venv`, HF cache under app-data, `dist/`).
- `README.md` quickstart: `uv sync`, `uv run python -m glimpse`.
- `git init` + initial commit (this is a fresh repo).

### 2. Core: config + db + store
- `config.py`: resolve app-data dir via `platformdirs` (added dep), e.g. `%LOCALAPPDATA%\Glimpse` on Windows; `db.sqlite`, `models/` subdir (unused v0.1 but created). Default settings + hardware-profile defaults.
- `db.py`: open connection, `load` `sqlite-vec` extension safely (try/except with clear message), create schema from spec §3 with `IF NOT EXISTS`, add `vec_chunks` virtual table (`vec0`, 384 dims) keyed to `chunks.id`, and `chunks_fts` FTS5 table over `snippet` + `file_id`. Triggers to keep FTS in sync. Migrations as a simple `schema_version` row mechanism.
- `store.py`: typed functions for add/update/remove files, chunks, locations, file_type_settings, settings; batch insert embeddings into the vec table; `remove_location_data(location_id)`.
- Setting `content_hash` = SHA-256 of file bytes (chunked reader) so unchanged files are no-ops on rescan (acceptance criterion).

### 3. Extractors (text/code/pdf only for v0.1)
- `base.py`: `Extractor` protocol `extract(path) -> Gist + list[Chunk]`; `Chunk{type, snippet(~150 char), position_meta}`; registry mapping file-type category -> extractor; honors file cap (text ~150 chunks, pdf ~200). Past cap: **hierarchical summarization** first cut = a simple centroid/leading-sentence merge producing fewer merged chunks (no model needed; keep it deterministic and clearly marked as a v0.1 simplification with a TODO for model-based summarization post-v0.3).
- `text.py`: paragraph splitter, snippet truncation, file gist = first ~300 chars of leading paragraph.
- `code.py`: language-aware chunker using regex heuristics per language (def/class for Python, fn/class for JS/TS, etc.); fallback fixed 150-char chunks when heuristic misses. Keep dependency-free (no tree-sitter) for v0.1; note tree-sitter as a future improvement.
- `pdf.py`: `pypdf` per-page text, chunk per page/paragraph, same cap/hierarchical-merge rule.
- Each extractor also produces the file `gist` (~300 chars).

### 4. Embedder
- `embedder.py`: `Embedder` ABC with `dim`, `embed_texts(list[str]) -> np.ndarray[float32]`. `SentenceTransformersEmbedder` loads `BAAI/bge-small-en-v1.5` (CPU). Lazy-load on first use so app starts fast and model download is transparent (with a one-time "Preparing model…" state surfaced to UI).

### 5. Resource governor + queue
- `queue.py`: thread-safe `JobQueue` with priority (pending rescans > new files), dedupe by `file_id`, pause/resume, `Max Effort` flag, depth counter for ETA.
- `governor.py`: `ResourceGovernor.poll() -> Decision{run, batch_size, sleep_ms}`. Signals: `psutil.cpu_percent()`, battery level, idle (Windows `GetLastInputInfo` via `ctypes`/`win32api`), `pynvml` GPU load if available else "no GPU". Duty-cycle: small batch -> re-check -> sleep proportional to load. Idle gate: full rate only after N min idle. **Max Effort** flag suspends governor (normal priority, ignores idle gate).
- Worker process/thread: single background `threading.Thread` (worker count from profile) drains the queue through the governor; calls `indexer.process(job)`.

### 6. Watcher + indexer
- `watcher.py`: `watchdog.Observer` per enabled location; on create/modify enqueues a reindex job, on delete removes file rows (and cascades chunks); respects `file_type_settings` (skip disabled categories and never enqueue them) and `enabled` location flag (start/stop observers on toggle).
- `indexer.py`: `process(path)`: hash check (mtime + sha256) -> no-op if unchanged; else run extractor -> embed chunks (batched through embedder) -> store in DB; update `files.status`. All behind the governor's per-batch check.

### 7. Search (hybrid)
- `search.py`: embed query -> `sqlite-vec` top-N by cosine (`vec_distance`/`k` search) + FTS5 `bm25()` keyword top-N -> normalize & merge scores -> re-rank (weighted sum, configurable) -> return `Hit{file_id, path, file_type, snippet, mtime, score}`. Pure local, fully offline.

### 8. Backend (FastAPI)
- `backend.py`: `GET /api/search?q=...` -> hits; `GET /api/state` (queue depth, governor mode, indexing status, "preparing model"); `POST /api/perf/max_effort` (on/off), `GET/POST /api/perf` (governor thresholds + profile); `GET/POST /api/locations` (list/add/remove/enable); `GET/POST /api/filetypes` (per-category toggles). Serves `/static/*`. State changes propagate to watcher/governor live.

### 9. Tray + hotkey + windows
- `tray.py`: `pystray` icon (idle only; spec says "tray icon only when idle"), menu: Search, Toggle Max Effort, Pause/Resume, Settings, Quit. Toggling opens the search/settings windows.
- `hotkey.py`: `keyboard` global hotkey (default `Ctrl+Space`, configurable later) -> open search popup.
- `app.py`: threads = uvicorn server (daemon thread) + tray (main thread) + worker thread + watcher observers. Store shared app state in a small `AppState` singleton accessible to backend and tray. Windows = `pywebview.create_window("Glimpse", "http://127.0.0.1:<port>/")` twice (search + settings) opened on demand.

### 10. Frontend (vanilla HTML/JS/CSS)
- `ui/static/index.html` + `app.js`: search box auto-focus, debounced `/api/search`, results list with path/snippet/type-icon/mtime, keyboard nav, click to open file (`start`/`os.startfile` via a backend endpoint — added carefully to avoid path traversal; canonicalize and require path under an indexed location).
- `ui/static/settings.html` + `settings.js`: four tabs; **Locations** (add path, enable/disable, remove) and **File Types** (per-category toggles) fully functional for v0.1; **Models** and **Performance** present but stubbed to "available in v0.2/v0.3" except Max Effort toggle (which we DO wire per spec).
- All calls go to FastAPI; no business logic in JS.

### 11. Tests
- `tests/test_db.py`: schema creation + sqlite-vec load + FTS sync.
- `tests/test_store.py`: add/update file no-op on unchanged hash; remove location removes its files/chunks.
- `tests/test_extractors.py`: text, code, pdf chunking + cap behavior + gists within ~char budgets.
- `tests/test_governor.py`: thresholds -> Decision; Max Effort bypass.
- `tests/test_search.py`: index small fixtures -> hybrid search returns expected docs; disabling a category excludes them; removing location excludes them.

## Acceptance criteria checks (v0.1)
- Re-indexing unchanged file = no-op (hash check). → tested + realtime.
- App not visibly using CPU/GPU at idle on mid-range laptop. → governor duty-cycle + idle gate + low worker priority; at idle with empty queue the worker sleeps.
- Disabling a file-type category stops both indexing and watching for it immediately. → watcher filters by enabled categories; queue drops in-flight disabled jobs.
- Removing a location removes its indexed data. → `store.remove_location_data` cascades files+chunks; watcher observer stops.

## Out of scope for v0.1 (explicit)
- Images, Office docs, video, OCR, transcription, local-model downloader UI, remote LLM providers, answer synthesis, Linux. All are later milestones.

## Risks / fallbacks
- **sqlite-vec load failure** on a given SQLite build: detect and fall back to pure-Python cosine over a `chunks.embedding` BLOB column (small datasets fine for v0.1 demo). I'll implement the pure-Python fallback so v0.1 never hard-blocks on the extension.
- **sentence-transformers/torch download size** may surprise first run: surface "Preparing model…" in `/api/state` and in the UI; allow `local_only` style check later.
- **Global hotkey lib (`keyboard`)** needs care on Windows (admin in some cases); if blocked, we still open the popup from the tray icon, so the app is fully functional without the hotkey.
